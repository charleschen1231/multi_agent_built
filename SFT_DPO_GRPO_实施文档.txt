## 一、项目概述

### 1.1 项目定位

本项目是一个 **Multi-Agent System 的"搭建器 + 训练器"** 平台，核心功能：

1. 用户通过 **JSON 文件** 定义完整的多智能体系统（System Spec）
2. 基于 **GPT-4o API** 实现推理（Inference）
3. 支持三种训练模式：
   - **SFT**（监督微调，基于 ms-swift）
   - **DPO**（偏好优化，基于 ms-swift）
   - **GRPO**（强化学习，基于 verl）
4. 所有训练均支持 **System-Level**（多 Agent 级别），而非单模型级别
5. 蒸馏完成后可进行 **验证评估**（Phase 3）

### 1.2 蒸馏流程总览

```
┌──────────────────────────────────────────────────────────────┐
│                  三阶段蒸馏管线                                │
├──────────────┬───────────────────┬───────────────────────────┤
│  Phase 1     │   Phase 2         │   Phase 3                 │
│  Teacher     │   Student         │   Validation              │
│  Rollout     │   Training        │                           │
│              │                   │                           │
│  GPT-4o 生成 │  学生模型训练       │  对比学生 vs 教师输出      │
│  Ground      │  (SFT/DPO/GRPO)  │  计算蒸馏质量分数           │
│  Truth       │                   │                           │
└──────────────┴───────────────────┴───────────────────────────┘
```

### 1.3 技术栈

| 层级 | 技术 |
|------|------|
| 后端 API | FastAPI + Uvicorn |
| 前端 | 原生 HTML/CSS/JS（静态文件） |
| 数据库 | SQLite + SQLAlchemy |
| SFT/DPO 训练 | ms-swift（subprocess 调用） |
| GRPO 训练 | verl（subprocess 调用） |
| LLM 推理 | OpenAI API (GPT-4o) / Qwen API / 本地模型 |
| 模型选择 | ModelScope 魔塔社区 |

## 三、JSON 配置规范

### 3.1 SFT 训练配置（文档 §8.1）

```json
[
  {
    "agent_id": "planner",
    "model": { "name_or_path": "Qwen2.5-32B-Instruct" },
    "instruction_prompt": {
      "instruction": "Planner：生成计划。",
      "prompt_template": "用户需求：{{input.user_request}}\n输出 JSON plan："
    },
    "input": [{ "from": "user", "key": "user_request" }],
    "output": [{ "key": "plan", "to": [{ "agent": "infer", "as": "plan" }] }],
    "training": {
      "mode": "sft",
      "trainable": true,
      "dataset": { "input_key": "user_request" },
      "ground_truth": {
        "output_key": "plan",
        "gt_key": "plan_gt"
      },
      "loss": { "type": "ce", "weight": 0.3 },
      "train_parameters": {
        "lr": 2e-5,
        "batch_size": 4,
        "num_epochs": 3
      }
    }
  }
]
```

**关键字段说明：**

| 字段 | 说明 |
|------|------|
| `training.mode` | 训练模式：`sft` / `dpo` / `grpo` |
| `training.trainable` | 是否参与训练 |
| `training.ground_truth.gt_key` | 数据集中 ground truth 的字段名 |
| `training.loss.weight` | 该 Agent 的损失权重 |
| `training.train_parameters` | Agent 专属超参数（覆盖默认值） |

### 3.2 DPO 训练配置

```json
{
  "agent_id": "planner",
  "model": { "name_or_path": "Qwen2.5-0.5B-Instruct" },
  "instruction_prompt": { ... },
  "training": {
    "mode": "dpo",
    "trainable": true,
    "ground_truth": { "gt_key": "plan_gt" },
    "loss": { "type": "dpo", "weight": 1.0 },
    "train_parameters": {
      "lr": 5e-7,
      "beta": 0.1,
      "num_epochs": 3,
      "batch_size": 2
    }
  }
}
```

**DPO 数据来源：**
- **chosen**（偏好回答）= 教师模型（GPT-4o）输出的 Ground Truth
- **rejected**（非偏好回答）= 学生模型的输出

### 3.3 GRPO 训练配置（文档 §8.2）

```json
[
  {
    "agent_id": "planner",
    "model": { "name_or_path": "Qwen2.5-32B-Instruct" },
    "instruction_prompt": {
      "instruction": "Planner：生成计划。",
      "prompt_template": "用户需求：{{input.user_request}}\n输出 JSON plan："
    },
    "input": [
      { "from": "user", "key": "user_request" }
    ],
    "output": [
      { "key": "plan", "to": [ { "agent": "infer", "as": "plan" } ] }
    ],
    "training": {
      "mode": "grpo",
      "trainable": true,
      "policy_role": "actor",
      "learn_from": [ "reward.final" ]
    }
  },

  {
    "agent_id": "infer",
    "model": { "name_or_path": "Qwen2.5-32B-Instruct" },
    "instruction_prompt": {
      "instruction": "Infer：根据计划生成答案。",
      "prompt_template": "Plan：{{input.plan}}\n问题：{{input.user_request}}\n答案："
    },
    "input": [
      { "from": "user", "key": "user_request" },
      { "from": "planner", "key": "plan" }
    ],
    "output": [
      { "key": "draft_answer", "to": [ { "agent": "checker", "as": "draft_answer" } ] }
    ],
    "training": {
      "mode": "grpo",
      "trainable": true,
      "policy_role": "actor",
      "learn_from": [ "reward.final" ]
    }
  },

  {
    "agent_id": "checker",
    "model": { "name_or_path": "Qwen2.5-32B-Instruct" },
    "instruction_prompt": {
      "instruction": "Checker：输出最终答案（也可只做格式修正）。",
      "prompt_template": "问题：{{input.user_request}}\n候选答案：{{input.draft_answer}}\n输出 final_answer："
    },
    "input": [
      { "from": "user", "key": "user_request" },
      { "from": "infer", "key": "draft_answer" }
    ],
    "output": [
      { "key": "final_answer", "to": [ { "user": true } ] }
    ],
    "training": {
      "mode": "grpo",
      "trainable": false,
      "rollout": {
        "dataset_input_key": "user_request",
        "max_steps": 3,
        "record_trajectory": true
      },
      "reward_spec": [
        {
          "reward_id": "reward.final",
          "type": "gt_match_or_rule_or_model",
          "on": { "agent": "checker", "output_key": "final_answer" },
          "reference": { "from": "dataset", "key": "final_answer_gt" },
          "weight": 1.0,
          "apply_to_agents": ["planner", "infer"]
        }
      ],
      "grpo_hparams": {
        "backend": "verl",
        "batch_size": 64,
        "mini_batch_size": 8,
        "kl_coef": 0.01,
        "clip_range": 0.2,
        "advantage": "gae"
      }
    }
  }
]
```

**GRPO 训练关键字段说明：**

| 字段 | 说明 |
|------|------|
| `training.policy_role` | Agent 在 GRPO 中的角色：`actor`（可训练策略）或 `critic`（仅评估，不训练） |
| `training.learn_from` | Agent 从哪些 reward_id 学习（reward_id 白名单列表）。只有 `reward_id` 在此列表中的 reward 才会参与该 Agent 的梯度更新 |
| `training.trainable` | 是否参与训练（true=训练，false=仅作为 pipeline 中的固定节点） |

### 3.4 高级 Reward Spec（每个 Agent 独立 Reward）

```json
"reward_spec": [
  {
    "reward_id": "reward.plan_quality",
    "type": "llm_judge",
    "on": { "agent": "planner", "output_key": "plan" },
    "judge_model": { "name_or_path": "gpt-4o-mini" },
    "criteria": "Evaluate plan quality: completeness, feasibility, clarity.",
    "weight": 0.3,
    "apply_to_agents": ["planner"]
  },
  {
    "reward_id": "reward.format",
    "type": "rule",
    "on": { "agent": "infer", "output_key": "draft_answer" },
    "rule": "must_follow_format_v1(description)",
    "weight": 0.2,
    "apply_to_agents": ["infer"]
  },
  {
    "reward_id": "reward.final",
    "type": "gt_match_or_model",
    "on": { "agent": "checker", "output_key": "final_answer" },
    "reference": { "from": "dataset", "key": "final_answer_gt" },
    "weight": 1.0,
    "apply_to_agents": ["planner", "infer"]
  }
]
```

**Reward 类型说明：**

| type | 说明 | 实现方式 |
|------|------|---------|
| `gt_match` / `gt_match_or_rule_or_model` | Ground Truth 匹配 | Token F1 + ROUGE-L |
| `rule` | 规则匹配 | JSON 格式 / 长度 / 正则 / 包含检查 |
| `llm_judge` | LLM 评判 | 调用 GPT-4o API，解析 0.0~1.0 分数 |

## 四、各模块实现细节

### 4.1 SFT Trainer（`training/sft_trainer.py`）

**状态：已完成（前次迭代）**

**核心方法：**

| 方法 | 功能 |
|------|------|
| `prepare_agent_sft_data()` | 为单个 Agent 生成 SFT 训练数据（ms-swift messages 格式） |
| `prepare_all_agents_sft_data()` | 遍历所有 trainable Agent，批量生成数据 |
| `train_with_api()` | subprocess 执行 `swift sft` 命令，实时日志流 |
| `train_system_level()` | System-Level 编排：数据生成 → 顺序训练 → 结果聚合 |
| `_render_prompt_template()` | 渲染 `{{input.xxx}}` 模板变量 |
| `_clean_datasets_cache()` | Windows 上 HuggingFace datasets 缓存清理 |

**训练流程：**

```
1. 遍历 config_json，找到 training.mode=="sft" && trainable==true 的 Agent
2. 为每个 Agent:
   a. 读取数据集，提取 gt_key 字段作为 ground truth
   b. 用 prompt_template + input_data 渲染 user prompt
   c. 生成 {messages: [system, user, assistant]} 格式的 JSONL
3. 顺序训练每个 Agent（subprocess 调用 swift sft）
4. 汇总所有 Agent 的训练结果
```

### 4.2 DPO Trainer（`training/dpo_trainer.py`）

**状态：本次实现**

**核心方法：**

| 方法 | 功能 |
|------|------|
| `prepare_preference_data()` | 从轨迹数据提取偏好对（基础方法） |
| `build_preference_pairs_from_trajectories()` | 从 TrajectoryRecorder 格式构建偏好对 |
| `build_preference_pairs_from_trajectory_file()` | 从 JSONL 轨迹文件构建偏好对 |
| `prepare_agent_dpo_data()` | 为单个 Agent 生成 DPO 数据（SWIFT DPO 格式） |
| `prepare_all_agents_dpo_data()` | 批量为所有 DPO Agent 生成数据 |
| `train_with_subprocess()` | subprocess 执行 `swift dpo` 命令 |
| `train_system_level()` | System-Level DPO 编排 |

**DPO 数据格式（SWIFT DPO 兼容）：**

```json
{
  "messages": [
    {"role": "system", "content": "你是 Planner Agent"},
    {"role": "user", "content": "用户需求：帮我制定学习计划"}
  ],
  "chosen": "1. 分析学习目标 2. 制定时间安排 3. 选择学习资源",
  "rejected": "好的我来帮你",
  "metadata": {"agent_id": "planner", "sample_index": 0}
}
```

**偏好对来源（三种方式）：**

**方式一：自动从轨迹生成（Teacher vs Student）**
- `chosen` = 教师模型（GPT-4o）输出的 ground truth（从数据集 gt_key 获取）
- `rejected` = 学生模型的输出（从轨迹文件获取）
- 对应方法：`prepare_agent_dpo_data()` + `build_preference_pairs_from_trajectories()`

**方式二：用户直接提供偏好对（说明文档 §11）**
- 用户直接提供 chosen 和 rejected 对，无需先执行 Teacher Rollout
- 对应方法：`prepare_preference_data_from_pairs()`
- 数据格式：
```json
[
  {
    "prompt": "用户需求：帮我制定学习计划",
    "input": "",
    "chosen": "1. 分析学习目标 2. 制定时间安排 3. 选择学习资源",
    "rejected": "好的我来帮你",
    "metadata": {"agent_id": "planner"}
  }
]
```

**方式三：从轨迹 JSONL 文件自动提取**
- 自动读取 TrajectoryRecorder 生成的 JSONL 文件，提取偏好对
- 对应方法：`build_preference_pairs_from_trajectory_file()`

**训练命令：**
```bash
swift dpo \
  --model <student_model_path> \
  --ref_model <ref_model_path> \
  --dataset <dpo_data.jsonl> \
  --output_dir <output_dir> \
  --learning_rate 5e-7 \
  --beta 0.1 \
  --num_train_epochs 3 \
  --tuner_type lora \
  --lora_rank 8 \
  --fp16 true
```

### 4.3 GRPO Trainer（`training/grpo_trainer.py`）

**状态：本次实现**

**核心方法：**

| 方法 | 功能 |
|------|------|
| `compute_rewards()` | 根据 reward_spec 计算所有轨迹的奖励 |
| `_compute_gt_match_reward()` | GT 匹配奖励（Token F1 + ROUGE-L） |
| `_compute_rule_reward()` | 规则奖励（JSON/长度/正则/包含/前后缀） |
| `_compute_llm_judge_reward()` | LLM 评判奖励（实际调用 GPT-4o API） |
| `prepare_agent_grpo_data()` | 为单个 Agent 生成 GRPO 数据 |
| `train_with_subprocess()` | subprocess 执行 verl GRPO 训练 |
| `train_system_level()` | System-Level GRPO 编排 |
| `_extract_reward_spec_for_agent()` | 提取与指定 Agent 相关的 reward_spec（支持 learn_from 过滤） |
| `_extract_grpo_hparams()` | 从系统配置提取 GRPO 超参数 |

**learn_from 过滤逻辑：**
- 每个 trainable GRPO Agent 可通过 `training.learn_from` 指定 reward_id 白名单
- `_extract_reward_spec_for_agent()` 先按 `apply_to_agents` 过滤，再按 `learn_from` 过滤
- 如果 `learn_from` 未配置，则使用所有 `apply_to_agents` 包含该 Agent 的 reward
- 示例：`"learn_from": ["reward.final"]` 表示该 Agent 只从 `reward.final` 学习，忽略其他 reward

**Reward 计算详情：**

**gt_match 奖励（多层匹配策略）：**
1. 完全匹配 → 1.0
2. Token-level F1 Score（分词后计算精确率/召回率）
3. ROUGE-L（最长公共子序列 F1）
4. 返回 F1 和 ROUGE-L 中的最大值

**rule 奖励（规则引擎）：**
- `json` / `must_follow_format` → JSON 格式校验
- `length` → 长度约束（min_length, max_length）
- `regex` / `pattern` → 正则表达式匹配
- `contains` → 必须包含指定字符串
- `starts_with` / `ends_with` → 前缀/后缀检查

**llm_judge 奖励（GPT-4o 评判）：**
1. 构建评判 Prompt（包含评估标准、Agent 输出、参考 GT）
2. 调用 `ModelFactory.create_llm(judge_model)` 创建 LLM 实例
3. 解析返回的 0.0~1.0 数值分数
4. 结果缓存避免重复 API 调用

**GRPO verl 配置：**
```json
{
  "model": { "path": "<model_path>", "type": "<model_type>" },
  "data": {
    "train_files": "<data_file>",
    "train_batch_size": 64,
    "max_prompt_length": 2048
  },
  "algorithm": {
    "kl_penalty": "kl",
    "kl_ctrl": { "kl_coef": 0.01 },
    "adv_estimator": "gae"
  },
  "actor_rollout_ref": {
    "actor": {
      "optim": { "lr": 1e-6 },
      "ppo_mini_batch_size": 8,
      "clip_range": 0.2
    },
    "rollout": { "name": "vllm", "n": 4 }
  }
}
```

### 4.4 评估器（`evaluation/evaluator.py`）

**状态：本次实现**

**SystemEvaluator 类：**

| 方法 | 功能 |
|------|------|
| `evaluate_agent()` | 评估单个 Agent 的蒸馏效果 |
| `evaluate_system()` | 系统级蒸馏效果评估 |
| `evaluate_from_trajectory_files()` | 从轨迹文件直接评估 |
| `evaluate_trajectory_consistency()` | 评估多 Agent 轨迹链路一致性 |
| `save_report()` | 保存评估报告到 JSON 文件 |

**评估指标：**

| 指标 | 说明 | 计算方式 |
|------|------|---------|
| Exact Match Rate | 精确匹配率 | 完全相同的样本占比 |
| Token F1 | Token 级 F1 分数 | 分词后计算精确率/召回率 |
| ROUGE-L | 最长公共子序列 F1 | 动态规划 LCS |
| Char Overlap | 字符级 Jaccard 相似度 | 基于字符 bigram |
| Length Ratio | 长度比率 | min(len_s, len_t) / max(len_s, len_t) |
| **Distillation Quality Score** | **蒸馏质量综合分** | **0.3×EM + 0.3×F1 + 0.2×ROUGE-L + 0.2×CharOverlap** |

**质量等级：**

| 分数范围 | 等级 |
|---------|------|
| ≥ 0.9 | A (Excellent) |
| ≥ 0.75 | B (Good) |
| ≥ 0.6 | C (Acceptable) |
| ≥ 0.4 | D (Poor) |
| < 0.4 | F (Failed) |

**评估报告结构：**
```json
{
  "status": "completed",
  "overall_quality_score": 0.7823,
  "agents_evaluated": 3,
  "agent_results": [
    {
      "agent_id": "planner",
      "sample_count": 50,
      "metrics": {
        "exact_match_rate": 0.12,
        "avg_token_f1": 0.78,
        "avg_rouge_l": 0.72,
        "distillation_quality_score": 0.65
      }
    }
```

## 五、API 接口文档

### 5.1 训练任务管理

#### 创建训练任务

```
POST /api/training/jobs
```

**请求体：**
```json
{
  "name": "MathSolver_SFT_v1",
  "type": "sft",
  "training_type": "sft",
  "description": "数学解题系统 SFT 蒸馏",
  "config_id": 1,
  "dataset_id": 2,
  "hyperparameters": {
    "lr": 2e-5,
    "num_epochs": 3,
    "batch_size": 4,
    "use_lora": true,
    "lora_rank": 8
  },
  "data_source": "dataset",
  "training_mode": "auto"
}
```

**training_type 可选值：**
- `"sft"` — 强制使用 SFT 训练
- `"dpo"` — 强制使用 DPO 训练
- `"grpo"` — 强制使用 GRPO 训练
- `"auto"` — 自动检测（根据 JSON 配置中的 `training.mode` 决定）

**training_mode 可选值：**
- `"auto"` — 自动检测（多 Agent 时使用 System-Level）
- `"system"` — 强制 System-Level 模式
- `"single"` — 强制单模型模式（向后兼容）

#### 获取训练任务详情

```
GET /api/training/jobs/{job_id}
```

**响应中的 metrics 字段结构（System-Level 模式）：**
```json
{
  "status": "completed",
  "mode": "system_level",
  "agents": [
    {
      "agent_id": "planner",
      "status": "completed",
      "model": "Qwen/Qwen2.5-0.5B-Instruct",
      "output_dir": "/path/to/output",
      "final_loss": 0.234,
      "loss_weight": 0.3,
      "elapsed_seconds": 180.5
    }
  ],
  "overall_message": "所有 3 个 Agent 训练完成"
}
```

`mode` 可能值：`system_level`、`system_level_dpo`、`system_level_grpo`、`mixed`

#### 验证蒸馏效果

```
POST /api/training/jobs/{job_id}/validate
```

**请求体（可选）：**
```json
{
  "student_trajectory_file": "/path/to/student.jsonl",
  "teacher_trajectory_file": "/path/to/teacher.jsonl"
}
```

**响应：**
```json
{
  "job_id": 1,
  "validation_report": {
    "overall_quality_score": 0.78,
    "quality_grade": "B (Good)",
    "agent_results": [...]
  },
  "report_file": "/path/to/eval_report.json"
}
```

#### 停止训练任务

```
POST /api/training/jobs/{job_id}/stop
```

#### 删除训练任务

```
DELETE /api/training/jobs/{job_id}
```

#### 部署训练好的模型

```
POST /api/training/jobs/{job_id}/deploy
```

**请求体：**
```json
{
  "agent_id": "planner",
  "create_new_version": true
}
```

### 5.2 训练模式路由逻辑

```
TrainingJobManager.run_training()
│
├── _detect_training_mode(config_json, training_type)
│   ├── 如果 training_type 明确指定 → 使用该类型
│   └── 否则扫描 agents 的 training.mode → 返回主导类型
│
├── if detected_type == "dpo" → dpo_trainer.train_system_level()
├── if detected_type == "grpo" → grpo_trainer.train_system_level()
├── if detected_type == "mixed" → 按顺序执行:
│   ├── sft_trainer.train_system_level() (SFT agents)
│   ├── dpo_trainer.train_system_level() (DPO agents)
│   └── grpo_trainer.train_system_level() (GRPO agents)
├── if detected_type == "sft" → sft_trainer.train_system_level()
└── else → sft_trainer.train_with_api() (单模型兼容模式)
```

## 八、使用流程

### 8.1 完整蒸馏流程

1. **定义系统** — 上传 JSON 配置文件（包含 Agent 定义 + 训练配置）
2. **上传数据集** — 上传 JSONL 数据集（包含 ground truth 字段）

## 九、注意事项与已知限制

### 9.1 环境要求

- **Python**: ≥ 3.8
- **ms-swift**: SFT 和 DPO 训练依赖 ms-swift (`pip install ms-swift`)
- **verl**: GRPO 训练依赖 verl (`pip install verl[all]`)
- **GPU**: 训练需要 CUDA 支持的 GPU；CPU 环境下 Flash Attention 自动禁用
- **Windows**: 已处理 HuggingFace datasets 缓存文件冲突问题

### 9.2 已知限制

1. **GRPO verl 集成**: verl 的实际 CLI 入口点可能因版本不同而变化，`_build_verl_command()` 可能需要根据实际安装调整
2. **LLM Judge 缓存**: 缓存基于 response 前 200 字符的 hash，极端情况下可能误命中
3. **Mixed Mode**: 多训练类型混合执行时，各类型之间无依赖管理（顺序执行）
4. **轨迹文件查找**: `_find_trajectory_file()` 使用最近文件策略，可能需要更精确的关联机制

### 9.3 扩展点

- 可在 `reward_functions` 字典中注册自定义奖励函数
- 可通过 `training.train_parameters` 为每个 Agent 定制超参数
- 评估器支持自定义指标扩展
